# Personal memory

Coding memory is about projects. Personal memory is about a relationship. It is what lets
a personal AI be the same someone tomorrow that it was today: with its own voice, its own
understanding of the person it works with, and a memory of what they have been through
together.

It is a separate capability, stored separately, and off unless you turn it on.

## What it holds

### The foundation

Four documents, each with one current version:

| Document | What it is |
|---|---|
| **Soul** | Who the agent is, and how it speaks |
| **User** | Who its person is |
| **Identity** | Its name, its nature, how it understands itself |
| **Core** | The few memories essential to remaining itself |

The foundation is **authored**, never generated by a background job. It is written by the
agent itself in conversation, or by its operator. When present it is loaded first and
whole, in that order, at the start of every session. This is the part that carries
personality: change the model underneath, and the agent that wakes up still reads the same
Soul.

### The living record

Four kinds of record that grow over time:

| Record | What it is |
|---|---|
| **People** | Who is in the person's life |
| **Relationships** | How those people relate to the person, and to each other |
| **Experiences** | Things that happened |
| **Reflections** | What the agent has come to understand |

## How it grows

**In conversation.** The agent can read, search and edit its own memory with a small set
of tools, and does so on its own judgement. There is no approval queue.

**By extraction.** A background worker reads recent conversations and proposes candidate
memories. Each candidate must quote the source text it rests on.

**By reflection.** On a schedule (nightly by default) the agent runs a dedicated session
in which it reconsiders what it knows in the light of the new candidates, and edits People,
Relationships, Experiences and Reflections. Doing nothing is a valid outcome; it is told
not to rewrite for style.

The background workers cannot touch the foundation. Soul, User, Identity and Core change
only when they are deliberately authored.

## What keeps it honest

A memory about a person's life has to be more careful than a memory about a codebase.

- **Attribution.** Every record says what kind of knowledge it is: something the person
  said, something observed, something inferred, or the agent's own reflection. A guess is
  never stored as a fact.
- **Evidence.** Extracted candidates carry exact quotes from their source.
- **Full history.** Every edit is a new revision with a reason. Nothing is overwritten;
  any record can be read at any earlier revision, and rolled back.
- **Bounded context.** The personal context injected into a session has a size budget.
  A write that would push the foundation over budget is refused, so the agent can never
  write itself out of its own context window.
- **Kept apart.** Personal records live in their own tables. The coding tools, search and
  ingestion described elsewhere in this documentation never read them.
- **Bound by the host.** Which person and which agent a memory belongs to is set by the
  application that starts the server, never chosen by the model.

## More than one person

A personal agent may talk with more than its owner: family, colleagues, friends. With
multi-audience mode on, each person has their own audience. A person's sessions read and
write only their own records, plus the agent's shared Soul and Identity. The owner sees
across audiences.

## Turning it on

Personal memory needs a host that binds sessions to a person and injects the context:
it is designed for agents built on Tess Core.

```toml
[[data_stores]]
name = "my-agent"
type = "tess-core"
path = "~/.my-agent/sessions"
project = "assistant"

[storage]
data_dir = "~/.my-agent/memory"

[personal]
enabled = true
owner = "sam"                 # the person
agent = "assistant"           # the agent
audience = "owner"
context_budget = 6000         # bytes of personal context per turn
source_names = ["my-agent"]   # which sources may feed it
extraction_enabled = true
dream_enabled = true          # nightly reflection
dream_hour = 23
timezone = "Europe/London"
shadow = true                 # propose only; set false to publish
```

Start with `shadow = true`. Background workers then record what they *would* change
without changing it, so you can read their proposals before trusting them.

Spending can be bounded with `daily_model_calls`, `daily_token_budget` and per-job limits.

## The tools

A session bound to personal memory gets its own tools, separate from the coding ones:

| Tool | Purpose |
|---|---|
| `autobiography_context` | The foundation plus selected people and relationships, within the budget |
| `autobiography_get` | Read a record, or list a segment |
| `autobiography_search` | Search personal records |
| `autobiography_history` | Earlier revisions of a record |
| `autobiography_update` | Write or revise a record, with a reason |
